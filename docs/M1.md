# M1 — Build mode

**Done when** (DESIGN §11): place, rotate, stack, recolour, undo/redo, property grids, IndexedDB save/load.

Decisions (21 Nov 2026): objects come from an **inventory** (starting stock in `src/data/start.json`; M3's furniture shop adds to it); **objects only** — floor/wall paint waits for the paint stall in M3.

## What's in

- 15 objects in `src/data/objects.json` (furniture, small items, wall items, ceiling items, a rug), 8 recolour ramps, placeholder art for every rotation.
- Placement rules: owned tiles only, no overlap, rotation, small items on surfaces, wall items on back walls, ceiling items under the roof.
- Commands: place, move, rotate, recolour, pick up, sell (70%), 100-step undo/redo. Surfaces carry what stands on them.
- Property grids for all 8 properties, streamed to a heat overlay in build mode with a level readout.
- Build HUD: inventory drawer, actions, colour swatches, undo/redo, money (Myanmar digits), refusal messages. Desktop keys: B, R, Esc, Delete, M, Enter, Ctrl+Z / Ctrl+Shift+Z.
- Saves: IndexedDB in the worker, autosave, boot load with the catch-up rule, `navigator.storage.persist()` after the first build, save codes in Settings.

## Known limits (BACKLOG / later milestones)

- Property spread ignores walls; need checks arrive in M2/M5.
- Light overlay contrast is low on the placeholder shop floor.
- Multi-tile depth sorting uses the footprint's front tile; tall multi-tile objects next to characters may need sprite slicing (M2/M3).
- The recolour atlas has no eviction yet (fine for M1's object count).
